# Plan: our-adventures — Full-Stack Couples' Adventure Tracker

**Date:** 2026-04-11  
**Status:** Draft  
**Repo:** `VietThan/our-adventures` (submodule alongside `nyc-adventure`)

---

## Context

`nyc-adventure` is a frontend-only proof-of-concept Linh built: a single HTML file with all state in `localStorage`. It has great UX instincts (category wheel, surprise picker, seasonal tags, mark done + rate) but state doesn't sync between devices and can't be shared between Viet and Linh. This project makes it real — persisted, synced, and owned by both.

---

## Core Requirements

- Shared state: what Viet marks done, Linh sees immediately (and vice versa)
- Data persists across devices and browsers
- Preserve all UX ideas from `nyc-adventure` (categories, wheel nav, picker, ratings, seasons)
- Seed from the existing ~195 activities; add/edit/delete new ones
- Private — just the two of them
- AWS as cloud provider

---

## Key Decisions

### Auth
**Auth.js (NextAuth v5) with Google provider** — Google OAuth in ~10 lines of config, session stored as a signed JWT cookie (strategy: `"jwt"`), allowlist enforced in the `signIn` callback against the two known emails. No AWS auth service needed.

Auth.js requires server-side routes (`/api/auth/*`) to handle the OAuth callback, which means Next.js runs in **server mode** (not static export) — see Hosting below.

The Fastify API verifies Auth.js sessions by sharing the same `AUTH_SECRET` env var. The browser sends the Auth.js JWT cookie; Fastify validates it on every request.

### Frontend
**Next.js (App Router, server mode)** — React ecosystem, TypeScript, Tailwind. Runs as a Node.js process on EC2 (not a static export). Auth.js integrates natively with App Router.

### Backend
**Node.js (Fastify) on EC2 t4g.nano** — a single always-on instance running the API server as a systemd service. Connects directly to RDS in the same VPC — no Lambda cold starts, no RDS Proxy, no VPC subnet wiring for functions. Simple to reason about, simple to debug (SSH in, check logs). Managed by CDK (EC2 instance + Security Groups + IAM instance profile).

Deployed via **GitHub Actions**: on push to `main`, GHA SSHes into the instance, pulls the latest build artifact, runs migrations, and restarts the systemd service. No CodeDeploy agent needed.

### Database
**PostgreSQL on AWS RDS** — relational model is the right fit for this data (activities, completions, users have real foreign-key relationships). Use `db.t4g.micro` with a single-AZ RDS instance — simple, cheap (~$14–16/month), no Aurora overhead for a 2-user app. Managed by CDK. Migrations via `node-pg-migrate` (TypeScript-native, runs as a step in the deploy pipeline).

RDS sits in a private subnet; only the EC2 instance's Security Group is allowed to connect on port 5432. No public exposure.

### Infrastructure-as-Code
**AWS CDK (TypeScript)** — provisions VPC, RDS, EC2 instance, Security Groups. No S3/CloudFront stack, no auth stack. CDK is run manually (or via a dedicated GHA workflow) when infra changes. Day-to-day deploys do not touch CDK.

### CI/CD
**GitHub Actions** — three workflows:

| Workflow | Trigger | What it does |
|---|---|---|
| `deploy-app.yml` | push to `main` | Build API + web, rsync to EC2, run migrations, restart both systemd services |
| `deploy-infra.yml` | manual trigger only | `cdk deploy` for infra changes |

GHA authenticates to EC2 via an SSH deploy key (private key stored as GHA secret). No AWS OIDC needed for deploys since there's no S3/CloudFront to push to — the EC2 instance pulls from the artifact directly.

### Hosting
**EC2 — nginx reverse proxy** — both apps run on the same EC2 t4g.nano as systemd services:
- Next.js server on port `3000`
- Fastify API on port `3001`
- nginx listens on port `80`, routes: `/api/v1/*` → Fastify, everything else → Next.js

No S3 or CloudFront needed. The EC2 public IP (or future domain) is the single entry point.

### Domain (future)
Skip for now — EC2 public IP works while the app is private. When ready: buy domain via Cloudflare, point A record to EC2 IP, provision TLS via Certbot (Let's Encrypt) on the instance.

## Data Model (PostgreSQL)

```sql
-- Seeded from nyc-adventure; custom ones added by users
CREATE TABLE activities (
  id          SERIAL PRIMARY KEY,
  title       TEXT        NOT NULL,
  category    TEXT        NOT NULL,   -- cinema | food | bakery | arts | shows | explore | wellness | daytrip | free | classes
  season      TEXT        NOT NULL,   -- spring | summer | fall | winter | any
  notes       TEXT,                   -- personal commentary
  tip         TEXT,                   -- practical info (address, price, how to get there)
  is_custom   BOOLEAN     NOT NULL DEFAULT FALSE,
  added_by    TEXT,                   -- Google sub of creator (from Auth.js); NULL for seeded data
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- One row per Auth.js user (auto-created on first login)
CREATE TABLE users (
  id           TEXT        PRIMARY KEY,  -- Google account sub (stable, from Auth.js account.providerAccountId)
  email        TEXT        NOT NULL UNIQUE,
  display_name TEXT        NOT NULL,
  avatar_url   TEXT,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Each person's completion of an activity is independent
CREATE TABLE completions (
  activity_id  INT         NOT NULL REFERENCES activities(id) ON DELETE CASCADE,
  user_id      TEXT        NOT NULL REFERENCES users(id),
  completed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  rating       SMALLINT    CHECK (rating BETWEEN 1 AND 5),
  review       TEXT,
  PRIMARY KEY (activity_id, user_id)
);

CREATE INDEX ON activities (category);
CREATE INDEX ON completions (user_id);
```

**Key query patterns:**
- List by category → `WHERE category = $1 ORDER BY id`
- Activity with both users' status → LEFT JOIN completions twice (once per user id)
- All completions for a user → `WHERE user_id = $1`
- Random undone activity → `WHERE id NOT IN (SELECT activity_id FROM completions WHERE user_id = $1) ORDER BY RANDOM() LIMIT 1`

## API Surface

All routes prefixed `/api/v1`, protected by Auth.js JWT middleware on Fastify (verifies the session cookie using the shared `AUTH_SECRET`).

| Method | Path | Description |
|---|---|---|
| `GET` | `/activities` | List all activities (optional `?category=` filter) |
| `GET` | `/activities/:id` | Get single activity with both users' completion status |
| `POST` | `/activities` | Create a custom activity |
| `PUT` | `/activities/:id` | Update a custom activity (own only) |
| `DELETE` | `/activities/:id` | Delete a custom activity (own only) |
| `POST` | `/activities/:id/complete` | Mark done + optional rating |
| `DELETE` | `/activities/:id/complete` | Unmark |
| `GET` | `/activities/pick` | Surprise picker — returns random undone activity, optional `?category=` |
| `GET` | `/me` | Current user profile |
